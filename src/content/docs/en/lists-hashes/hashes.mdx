## Hashes — a flat dictionary under one key

Redis Hashes store multiple field-value pairs under a single key. Think of it as a flat dictionary or a row in a database — one key holds many named fields.

## HSET and HGET

`HSET key field value [field value ...]` sets one or more fields. Redis 7+ allows multiple field-value pairs in a single call. `HGET key field` retrieves one field by name. If the field does not exist, Redis returns `(nil)`.

```text
127.0.0.1:6379> HSET product:1 name "Redis Mug" price "12.99" stock "200"
(integer) 3
127.0.0.1:6379> HGET product:1 name
"Redis Mug"
127.0.0.1:6379> HGET product:1 price
"12.99"
127.0.0.1:6379> HGET product:1 missing-field
(nil)
```

export const hsetGetCode = `HSET product:1 name "Redis Mug" price "12.99" stock "200"
HGET product:1 name
HGET product:1 price
HGET product:1 missing-field`;

## HMGET and HGETALL

`HMGET key field [field ...]` fetches multiple fields in one round-trip and returns `(nil)` for any field that does not exist. `HGETALL key` returns every field-value pair in the hash as an alternating list of field names and values.

```text
127.0.0.1:6379> HMGET product:1 name stock
1) "Redis Mug"
2) "200"
127.0.0.1:6379> HGETALL product:1
1) "name"
2) "Redis Mug"
3) "price"
4) "12.99"
5) "stock"
6) "200"
```

export const hmgetCode = `HMGET product:1 name stock
HGETALL product:1`;

<TryRedis client:visible code={hmgetCode} />

## HDEL and HEXISTS

`HDEL key field [field ...]` removes one or more fields and returns the number of fields actually deleted. `HEXISTS key field` returns `1` if the field exists, `0` if it does not — useful for conditional logic without fetching the value itself.

```text
127.0.0.1:6379> HEXISTS product:1 price
(integer) 1
127.0.0.1:6379> HEXISTS product:1 color
(integer) 0
127.0.0.1:6379> HDEL product:1 price
(integer) 1
127.0.0.1:6379> HEXISTS product:1 price
(integer) 0
```

export const hdelCode = `HSET product:1 name "Redis Mug" price "12.99" stock "200"
HEXISTS product:1 price
HEXISTS product:1 color
HDEL product:1 price
HEXISTS product:1 price
HKEYS product:1
HVALS product:1
HLEN product:1`;

## HKEYS, HVALS, and HLEN

`HKEYS key` returns all field names. `HVALS key` returns all field values. `HLEN key` returns the total number of fields in the hash. After deleting `price` above, the hash now has two fields: `name` and `stock`.

```text
127.0.0.1:6379> HKEYS product:1
1) "name"
2) "stock"
127.0.0.1:6379> HVALS product:1
1) "Redis Mug"
2) "200"
127.0.0.1:6379> HLEN product:1
(integer) 2
```

## Expiring individual fields

`EXPIRE` works on a whole key, so for a long time a hash was all-or-nothing: every field lived and died together. Redis 7.4 changed that with **field-level TTL**, and Redis 8 added three commands that fold the TTL into the read or write itself.

`HEXPIRE key seconds [NX | XX | GT | LT] FIELDS numfields field [field ...]` sets the TTL. Note the `FIELDS` keyword and the field **count** before the names — every command in this family takes them. It returns one number per field: `1` when the TTL was set, `-2` when the field does not exist, `0` when an `NX`/`XX`/`GT`/`LT` condition was not met. `HTTL` reads the remaining seconds and `HPERSIST` removes the TTL again.

```text
127.0.0.1:6379> HSET session:42 user "ana" csrf "t0ken"
(integer) 2
127.0.0.1:6379> HEXPIRE session:42 600 FIELDS 1 csrf
1) (integer) 1
127.0.0.1:6379> HTTL session:42 FIELDS 2 csrf user
1) (integer) 600
2) (integer) -1
```

A `-1` means the field has no expiration. Once the TTL runs out the field disappears on its own, and when the last field goes the key goes with it.

### HGETEX, HSETEX, and HGETDEL

These three Redis 8 commands each replace a small multi-command dance:

| Command | Shape | Replaces |
|---------|-------|----------|
| `HGETEX key [EX seconds \| PERSIST] FIELDS numfields field [field ...]` | read and re-arm the TTL | `HGET` + `HEXPIRE` |
| `HSETEX key [FNX \| FXX] [EX seconds \| KEEPTTL] FIELDS numfields field value [field value ...]` | write with a TTL | `HSET` + `HEXPIRE` |
| `HGETDEL key FIELDS numfields field [field ...]` | read and remove | `HGET` + `HDEL` |

`HGETEX` is the sliding-session primitive: read the field and push its expiry out in the same atomic call. `HSETEX` takes `FNX` (only if none of the fields exist) or `FXX` (only if all of them do), plus `KEEPTTL` to leave an existing expiry alone. `HGETDEL` is the one-shot read used for consume-once values like a one-time token.

```text
127.0.0.1:6379> HSETEX session:42 EX 900 FIELDS 1 csrf "fresh-token"
(integer) 1
127.0.0.1:6379> HGETEX session:42 EX 900 FIELDS 1 csrf
1) "fresh-token"
127.0.0.1:6379> HGETDEL session:42 FIELDS 1 csrf
1) "fresh-token"
127.0.0.1:6379> HGET session:42 csrf
(nil)
```

export const hashTtlCode = `HSET session:42 user "ana" csrf "t0ken"
HEXPIRE session:42 600 FIELDS 1 csrf
HTTL session:42 FIELDS 2 csrf user
HSETEX session:42 EX 900 FIELDS 1 csrf "fresh-token"
HGETEX session:42 EX 900 FIELDS 1 csrf
HGETDEL session:42 FIELDS 1 csrf
HGET session:42 csrf`;

<Callout title="A hash stores an object's fields under one key — memory-efficient">

Redis uses a compact encoding (listpack) for small hashes automatically. Instead of storing `product:1:name`, `product:1:price`, and `product:1:stock` as three separate string keys, one `HSET product:1 ...` stores them together under a single key — lower memory, fewer round-trips, and logical grouping.

</Callout>
